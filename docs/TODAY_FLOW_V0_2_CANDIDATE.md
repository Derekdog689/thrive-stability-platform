# THRIVE Today Flow v0.2 Candidate

Status: Approved UX candidate. Review and runtime validation required before merge or deployment.

## Purpose

Transform Today from a narrative-heavy dashboard into a visual-first participant story that can be scanned, understood, and acted on quickly on a phone.

## Frozen boundaries

- THRIVE personal support and the Trust Engine remain separate systems.
- Bank data remains observational evidence.
- Do not infer intent, irresponsibility, relapse, incapacity, or trust misuse from financial activity.
- Facts, patterns, explanations, and conclusions remain distinct.
- No schema change is required for this candidate.
- No production merge or deployment is authorized by this candidate.

## Participant design rules

1. Visual first. Words second.
2. Literal navigation and action language.
3. Plain factual state language.
4. Personality may react to facts, but never replace or distort them.
5. One dominant action at a time.
6. If a control already explains a choice, do not add prose explaining the control.
7. If a number or state can be seen, do not restate it in prose.
8. Motion communicates state, touch, and completion. It is not decoration.
9. The interface may show uncomfortable facts clearly. Clear does not mean condemning.
10. Participant progress is compared with the participant's own stated goals and recorded history, not other people.

## Wording corrections

Do not use phrases such as:

- "Today looks heavy"
- "Keep this moving"

Prefer literal phrases such as:

- "Hard day"
- "Not sure today"
- "Doing alright"
- "Feeling good"
- "Up next"
- "Your next step"
- "Continue your goal"

## Today story order

1. Arrive: short atmospheric greeting.
2. Orient: glance strip for Wellness, Goal, Money, and Support.
3. Act: one dominant current action.
4. See: visual money state.
5. Reflect: compact recent-history visual.
6. Connect: Support rises only when actionable.
7. Navigate: persistent simple bottom dock.

## Motion classes

- Ambient: slow background drift.
- State: progress fills, bars, dots, and status transitions.
- Touch: immediate press/lift feedback.
- Completion: completed item settles and makes room for the next useful state.

## Runtime pressure test

A participant should be able to understand the main state and next action while walking through a grocery store. If the screen requires reading paragraphs, remembering previous cards, or choosing among many equal options, the candidate has failed.
