## Why this candidate exists

The first forty THRIVE resources are not a Recovery catalog.

They are the initial **whole-person support library** for the questions THRIVE already creates across Wellness, Goals, Money, Recovery, and stability/navigation.

The canonical library stays grounded in real-world domains. THRIVE lanes supply the context for *why* a resource is being surfaced.

Example:

- Goal context: "I want to get my GED."
- Canonical resource domain: employment_education.
- Resource surfaced: official GED starting point.

Same resource, different reason it became useful.

This candidate preserves the existing six Recovery resources and proposes **34 additional entries**, bringing the working first-wave catalog to **40 total** if all are eventually approved.

## Existing six Recovery resources — preserve

1. A.A. Daily Reflections
2. Alcoholics Anonymous Meeting Support
3. Celebrate Recovery Group Support
4. NA Recovery Literature
5. Narcotics Anonymous Meeting Support
6. SMART Recovery Meeting Finder

These six remain the first Recovery slice. Deeper Recovery catalog expansion is future scale work, not part of the first forty.

---

## Routing principle

THRIVE should not behave like a link directory.

The intended model is:

**participant expresses a need → THRIVE understands the lane/context → THRIVE surfaces a small number of relevant verified resources → participant chooses what is useful**

No diagnosis, scoring, hidden inference, or automatic conclusion is required.

The first version of this can remain rules/context driven. AI is not required for the core architecture.

## Current canonical categories

The candidate uses the installed category set only:

- food_basic_needs
- identification_documents
- recovery_community_support
- employment_education
- transportation
- housing_information
- health_wellness_navigation
- financial_education
- government_programs_benefits
- other_not_sure

No schema change is proposed.

## Verification cadence

- **fast_changing** — local access, live schedules, portals, fares, current benefit processes, locator/finder tools.
- **moderate** — maintained educational guides, worksheets, application guidance, general service navigation.
- **stable** — durable foundational tools or official frameworks that change infrequently.

## Important observation: resources can serve multiple lanes

The canonical category should describe what the outside-world resource actually is.

The THRIVE context should describe why it is useful *right now*.

Examples:

- GED lives under employment_education but may surface from a Goal.
- CFPB savings guidance lives under financial_education but may surface from a Goal.
- Broward Transit lives under transportation but may surface because a participant is working on employment, meetings, or an appointment.
- MyPlate lives under health_wellness_navigation but may surface from Wellness, Money, or a healthy-routine Goal.
- Birth-certificate replacement lives under identification_documents but may surface because a job, benefits application, housing step, or school goal is blocked.

This is the connective tissue.

## Future intuitive routing candidate

No implementation is approved here, but the resource catalog should be built so a later routing layer can support mappings such as:

- expressed need / participant-selected topic
- source lane
- current goal topic
- Wellness self-selected area
- Money question type
- Recovery-support choice
- location / authorized program context

→ small set of verified Resource candidates.

The participant still chooses.

THRIVE does not infer eligibility, diagnosis, motivation, irresponsibility, relapse, incapacity, or intent.

## Local vs national scope

Several first-wave entries are intentionally South Florida / Broward-oriented because the current real-world deployment is there.

These should use the existing visibility model so local resources are not presented globally as though they apply everywhere.

As THRIVE expands geographically, equivalent local transportation, housing, benefits, workforce, and human-service access points can be added without changing the canonical model.
