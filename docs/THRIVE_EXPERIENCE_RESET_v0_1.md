# THRIVE Experience Reset v0.1

Date: 2026-09-30
Status: review-only candidate
Scope: participant experience, value return, continuity, visual experience, and engagement
Production impact: none
Database impact: none
Trust Engine impact: none

## Verified state

THRIVE's core participant plumbing is working. Today, Wellness, Goals, Money, Support, Today, cross-lane synthesis, history, and Money closeout are functioning. The current gap is not basic capability. The gap is that the experience records and reflects more effectively than it guides, supports, rewards, and carries a participant forward.

This candidate does not authorize implementation. It establishes a new experience direction for review.

## Frozen boundaries

- THRIVE participant support spine and the Trust Engine remain independent.
- No schema changes are authorized by this candidate.
- No historical record rewrites.
- No hard deletes.
- Bank or transaction data remains observational evidence only.
- No clinical diagnosis, relapse inference, incapacity conclusion, or fabricated explanation.
- Existing participant-owned facts may be connected across authorized THRIVE lanes without merging record ownership.
- No production implementation until this candidate is reviewed and explicitly approved.

## Why the reset is necessary

The current participant experience too often follows:

input -> summary -> card

The target experience is:

input -> understand -> useful return -> concrete action -> real resource -> follow-up -> adaptation -> visible progress -> story

THRIVE should not require the participant to do all of the interpretation themselves. The product should do more of the cognitive lifting while leaving choices with the participant.

The standard is no longer only "does this screen work?" The additional standard is:

- Would the participant voluntarily come back tomorrow?
- Did THRIVE make the next step easier to understand or do?
- Did the participant receive something useful in return for the information they provided?
- Did the interface visibly acknowledge meaningful effort, change, completion, or carry-forward?

## Experience Reset pillars

### 1. Value Loop

Every meaningful participant input should return meaningful value.

A return should do at least one of the following:
- reveal something useful the participant may not have noticed
- give a concrete action
- bring in a real resource
- help with a decision
- connect prior information to the current moment
- follow up on something previously attempted

A meaningful question should not end in a dead end. If THRIVE asks a question, the participant should have a place to answer it, and the answer should affect what comes next.

### 2. Directional Support

THRIVE should not assume the participant already knows how to translate insight into action.

Example:

Instead of only:
"Routine and confidence may be connected."

THRIVE could offer:
"What would help most right now?"
- sleep
- morning routine
- meeting/support
- one task
- something else

Choosing an option should open a useful next step rather than another generic prompt.

The design principle is:

> THRIVE does more of the cognitive lifting while the participant keeps the decision.

This should remain adult, direct, non-shaming, and grounded in participant-owned facts.

### 3. Resource Engine

THRIVE should bring useful things to the participant.

"Find a meeting" is incomplete support.

A useful return is:
- nearby or otherwise relevant meeting options
- meeting time and format
- directions or source link where available
- recovery literature or reading suggestions from appropriate sources
- practical worksheets or tools
- financial education
- employment, transportation, housing, food, or other relevant resources when the lane supports them

Resources should be real and source-grounded. THRIVE should not fabricate options.

### 4. Follow-up Engine

THRIVE should remember what it suggested, what the participant chose, and whether the attempt helped.

Follow-up should be specific to the prior action.

For example:
- Were you able to find a meeting?
- Did you read the item you saved?
- Did you contact anyone?
- Which part helped?
- What got in the way?

If something did not help, THRIVE should change direction rather than repeat the same suggestion.

### 5. Story

Story is the accumulation layer.

Wellness produces signals.
Goals produce movement.
Money produces cycles and patterns.
Support produces help-seeking and response history.

Story should answer:
- What has been happening?
- What changed?
- What did I do?
- What did I finish?
- What keeps returning?
- What remains unfinished?
- What should carry forward?

Story should not simply summarize records. It should make the participant's recent activity understandable as one continuing experience while preserving the source lane for each fact.

A possible day/week return could include:
- number of check-ins completed
- Goals completed, paused, resumed, or carried forward
- Money cycles closed
- Support threads started or continued
- recurring participant-owned needs
- one or two next items worth carrying forward

### 6. Visual Progress

Visual progress is part of the meaning, not decoration.

THRIVE should visibly distinguish:
- started
- moving
- repeated
- paused
- resumed
- partially completed
- completed
- carried forward

Meaningful completion should not simply disappear into an archive.

Potential visual treatments may include:
- a path advancing
- an arc filling
- a checkpoint changing state
- a card transforming
- a milestone surfacing
- a weekly rhythm becoming visible
- a Money cycle visually closing
- a carried-forward item visibly bridging into the next period

Partial completion should remain honest without becoming punitive.

Example:
"You aimed for 3 and completed 2."
Possible choices:
- keep going
- lower the target
- change the approach
- leave it here

No failure theater. No fake praise.

### 7. Atmosphere and visual experience

The visual experience has equal standing with functional improvement in this reset.

The current participant interface is consistent, but it feels too static and institutional. The palette, card stack, and repeated visual rhythm do not sufficiently communicate state, momentum, or accomplishment.

The next visual direction should explore:
- stronger depth and hierarchy
- richer contrast
- more distinctive lane identities
- tasteful motion
- contextual hero states
- milestone moments
- meaningful completion states
- morning/evening or cycle-based atmosphere where appropriate
- occasional illustration or ambient motion when it adds meaning
- a palette that can move beyond the current hospital/institutional feeling

No single visual trend is mandated. Glass, gradients, illustration, motion, stronger color, environmental imagery, and other approaches may be explored. The requirement is not a particular style. The requirement is that THRIVE feels alive, adult, polished, and worth returning to.

### 8. Adult directness

THRIVE can be supportive without being timid.

It may state grounded facts directly.

Example:
"You planned to do this three times and did it once."

Then:
"Want to try again, make it smaller, or change the plan?"

THRIVE should avoid both shame and artificial cheerleading.

The product may identify repeated participant-owned patterns when the evidence supports them. It should not invent motives, diagnoses, relapse conclusions, incapacity, or other unsupported interpretations.

### 9. Audience assumption

THRIVE should not be designed only for a participant who already has strong self-awareness, high bandwidth, or strong system-navigation skills.

The participant may:
- have limited bandwidth
- not know which systems or resources exist
- be uncertain what to do next
- have difficulty converting reflection into action
- need more structure on some days than others

The product should reduce that burden without removing participant agency.

## Two equal implementation tracks

Any future implementation candidate should carry two tracks together.

### Track A: Value + Story

Improve:
- participant return
- concrete action
- resources
- follow-up
- continuity
- Story

### Track B: Visual Experience

Improve:
- atmosphere
- visual hierarchy
- motion
- progress representation
- completion treatment
- milestone treatment
- lane identity
- visual cohesion

Track B must not be postponed as a cosmetic pass after functional work. It is part of the participant experience contract.

## First proving-ground recommendation

Do not redesign the entire product at once.

The first implementation candidate should prove one complete loop using Recovery Support because live participant use already provides strong evidence.

Target loop:

need -> understand -> retrieve real resources -> offer concrete actions -> participant chooses -> follow up -> adapt -> visible progress -> Story

The proving-ground candidate should also include a deliberate visual treatment so usefulness and visual life are tested together.

If that loop feels useful and alive, the same architecture can be extended to Money, Goals, Wellness, and Support.

## Visual direction work before production code

Before implementation, prepare a visual direction review using real THRIVE content.

The review should show alternative treatments for:
- Today
- Wellness
- Goals
- Money closeout
- Story
- completion
- partial completion
- carry-forward

Explore multiple visual languages rather than assuming the current palette or a single trend is correct.

Evaluate each direction against:
- clarity
- adult tone
- emotional payoff
- visual stimulation
- accessibility
- mobile usability
- whether progress can be understood before reading a paragraph
- whether the experience feels like THRIVE rather than a generic wellness or institutional app

## Acceptance criteria for the reset direction

Before implementation approval, the candidate should demonstrate that:

1. A participant receives a useful return for meaningful input.
2. A prompt has a real response path.
3. A recommended action can lead to a real next step or resource.
4. Prior choices can be followed up specifically.
5. Multiple lane events can be shown as one coherent Story without merging ownership.
6. Completion has visible and functional consequence.
7. Partial completion has a dignified visual state.
8. The visual system communicates movement, state, and accomplishment.
9. The experience remains usable on a phone.
10. The experience feels materially less institutional and materially more alive.
